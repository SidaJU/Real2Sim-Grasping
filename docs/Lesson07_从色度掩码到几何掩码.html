Lesson 07 · 从色度掩码到几何掩码

gs_mesh 的两个缺陷（破损 + 发白）是怎么定位、怎么修掉的：
一次「外观判据 → 几何判据」的替换，和一次「二维误差地图」驱动的变形修复。 对应脚本：22_render_gs_depth.py（扩展）、23b_gs_to_mesh_v2.py（新）、23c_compare_meshes.py（A/B）。
核心结论：v1 的掩码问的是「这个像素够不够彩」（外观判据）， 而真正该问的是「这个像素属不属于物体」（几何判据）。 判据错位导致物体上的白色区域被当成背景剔掉 → TSDF 无观测 → Marching Cubes 出洞。 换成世界坐标 footprint + 高度窗口 + 轮廓腐蚀的几何掩码后， Chamfer 5.00 → 3.00 mm（−40%），边界边（破洞周长）4566 → 1136（−75%）。

缺陷量化指标直观表现

2 · 根因链条

2.1 破洞：判据与目的错位

chroma = max(RGB) − min(RGB) > 40 → 白色插画 / 文字 / 高光被判为「背景」
↓
depth = depth × mask → 这些像素深度置 0（Open3D 视为无效观测）
↓
TSDF 在这些体素上从未累积任何观测
↓
SDF 场在该区域没有可靠的零交叉
↓
Marching Cubes 抽不出面 → 洞

这条链的关键在第一环：色度衡量的是外观（颜色饱和度），掩码想要的是语义（属不属于物体）。 两者只在「红盒子 + 白桌面」这个巧合下近似等价——换成白色物体，整张图会被 mask 掉，直接得到空网格。 所以这不是「当前物体有几个洞」的问题，而是管线不具备通用性。

2.2 发白：三帧平均把颜色「平均成灰」

v1 用原始照片做 TSDF 颜色来源
↓
Open3D RGB8 模式对每个体素做多帧加权平均
↓
逐帧曝光 / 白平衡差异 + 高光过曝像素 → 平均后饱和度坍塌

3 · 涉及的算法：为什么会有洞、为什么 acc 没用

3.1 TSDF 融合与 Marching Cubes：洞的数学成因

TSDF 在每个体素 x 上维护一个截断符号距离的加权平均：

SDF(x) = Σₖ wₖ(x) · sdfₖ(x)  /  Σₖ wₖ(x)

sdfₖ(x) = dₖ − tₖ(x)        第 k 帧中，沿该像素射线到表面距离 dₖ 与体素深度 tₖ(x) 之差
wₖ(x)   = 1, |sdfₖ| < sdf_trunc；否则 0      ← 只融合「表面附近 ±sdf_trunc」的观测

Marching Cubes 提取 SDF(x) = 0 的等值面。某区域若没有任何帧提供有效观测， 它的 SDF 分子分母都是 0（未定义）→ 不存在零交叉 → 不生成任何三角形 → 洞。 所以「洞」不是 Marching Cubes 的 bug，而是「输入观测的空洞」被忠实地传递到了输出。 修洞的唯一正路是修观测（掩码），事后补面只会伪造几何。

3.2 3DGS 的期望深度与累积不透明度

splatfacto 的 get_outputs()（splatfacto.py:644-649）返回四个量，其中两个和掩码设计直接相关：

accumulation = Σᵢ αᵢ·Tᵢ ∈ [0,1]        累积不透明度：射线被「实心几何」吸收的比例
                                        αᵢ = 第 i 个高斯的不透明度，Tᵢ = 到它为止的透射率

depth (ED)   = Σᵢ wᵢ·dᵢ / Σᵢ wᵢ        期望深度：按权重 wᵢ = αᵢTᵢ 加权平均的命中距离
实测打脸的一步：渲染 99 帧后打印 acc.mean() = 1.000（每一帧都是）。 原因：白色桌面的背景高斯也是不透明的，射线打在物体上 acc≈1，打在桌面上同样 acc≈1。 所以 acc > 0.5 根本分不开前景和背景——它只能当有效性检查 （acc=0 表示射线什么都没打到，此时 splatfacto.py:637 会把深度填成哨兵值）。 「用一个与颜色无关的信号分前景」这个思路是对的，但选错了信号。

3.3 色度判据为什么错：语义 ≠ 外观

误杀（False Negative）→ 洞误留（False Positive）→ 雾
机理白色插画 / 文字 / 高光的 chroma < 40彩色反光、彩色噪点、带颜色的 floater
后果深度置 0 → 无观测 → 洞伪表面被融进体素场

阈值 40 还是无依据的全局常数，不随光照、曝光、物体颜色自适应。

4.1 它在数据流里的位置

4.2 单帧掩码的五步（对应 23b_gs_to_mesh_v2.py 主循环）

  1. 取数据：读 depth_i.npy（÷SCALE=3.697 换算成米）、acc_i.npy、rgb_i.npy。
  2. 反投影到世界坐标：把每个深度像素变成 3D 点。 
    p_cam = ( (u−cx)·d/fx , (v−cy)·d/fy , d )      OpenCV 相机系（z 向前）
w2c   = inv(c2w @ FLIP)                      与 vol.integrate 用的是同一个矩阵
p_w   = (p_cam − t) @ R                      R = w2c[:3,:3],  t = w2c[:3,3]
    必须用同一个变换，否则掩码判据所在的坐标系和 TSDF 的不一致，掩码就白做了。
  3. 五条件取交集：
    条件阈值剔除什么
    深度有效0.01 < d < 0.8GS 深度空洞 / 哨兵值
    累积不透明度acc > 0.1射线什么都没打到（此时深度是 max 哨兵）
    footprint|x| < 0.083, |y| < 0.107桌面、背景墙等物体之外的一切
    高度窗口0.033 < z < 0.080桌面（与物体底面同高，靠 3 mm 余量剔除）
    轮廓腐蚀binary_erosion(it=8)掠射角被污染的轮廓/接触带一圈（见 §6）
  4. 应用：depth = np.where(m, depth, 0.0) —— 黑色像素深度变 0，Open3D 视为「此处无观测」， 既不加 SDF 也不加颜色。
  5. 送进 TSDF：与 GS 渲染色打包成 RGBD，vol.integrate(rgbd, intr, w2c)。

用 23d_coverage_check.py 实测：把最终网格均匀采样 4000 个点，逐点投影回每一帧， 统计「落在白区且观测深度与该点一致（±8 mm）」的次数：

部位点数平均被几帧看到中位从未被看到
顶面96236.2360
上段壁面179326.6220
下段壁面11788.9718

三个结论：

  1. 并集覆盖：表面完整性来自 63 帧的并集，不依赖任何单帧。顶面平均被 36 帧看到， 所以第 50 帧缺的那块由别的视角补上——没有任何一个顶面点从未被观测。
  2. 冗余抗噪：同一处被 ~23 帧重复观测，偏差被 TSDF 的加权平均投票掉。
  3. 弱区在下段壁面：均值只有 8.9 帧，是唯一出现「从未被看到」的地方—— 这正好对应 §10 的遗留限制（底部 6 mm 缺失）。腐蚀对观测本就稀缺的区域伤害最大。

4.5 这个 mask 和 3DGS 训练时的 mask 是一回事吗？

不是一回事，只是同名。两者都是「前景/背景二值图」，但作用阶段、作用对象、后果完全不同。 混淆它们会导致一个典型误解：以为「训练时加了 mask，重建就不用管了」。
训练 mask（Lesson 05）重建 mask（本 Lesson）
作用阶段训练时（nerfstudio，跑 30k 步之前）训练后（TSDF 重建时现算）
作用对象loss 计算：决定哪些像素参与梯度深度图：决定哪些像素的观测被融合
直接目的背景 loss=0 → 梯度=0 → 不 densify → 不长 floater背景/污染深度=0 → TSDF 看不见 → 不生成伪表面
判据图像空间的前景分割（chroma / SAM / 手工）世界坐标几何：footprint + 高度窗 + 腐蚀
影响对象改变模型本身（高斯数量、几何质量）不改模型，只改「我们从模型里取哪些观测」
迭代成本改了要重训（30k 步，小时级）改了秒级重跑重建，可反复试
本项目状态没用（22/23 脚本注释：this run was trained WITHOUT a mask）本次新建（23b）
两者的因果关系（本项目的关键）：正因为训练时没加 mask， 模型里混进了整张白桌面的背景高斯，所以重建侧才必须靠一个「几何掩码」去分辨「哪些深度属于物体」—— 重建掩码是在事后补偿训练掩码的缺失。
如果训练时用了 mask：背景干净、没有 floater，重建侧只需复用同一张前景分割图（投影到对应帧）即可， 世界坐标判据和腐蚀这套机制大半都不需要。

一句话区分：训练 mask 决定「模型学什么」，重建 mask 决定「我们从模型里拿什么」。

6 · 斗形变形的根因：掠射角下的期望深度污染

3DGS 的期望深度是沿射线加权平均：ED = Σ wᵢdᵢ / Σ wᵢ。 当射线近乎平行于壁面（掠射）时，同一根射线会以不小的时间权重先后穿过 「壁面高斯」和「壁面后方桌面上的高斯」，两个命中被平均成一个——落点被拉向更远处。 在图像上，这类像素恰好集中在物体轮廓与桌面的接触带。

修复算法：二值腐蚀（binary erosion）

对每帧的 2D 掩码 m 做形态学腐蚀：

m ⊖ B = { p : Bₚ ⊆ m }        结构元 B = 8×8 邻域（iterations=8 的 3×3 十字等价于 8 次膨胀式收缩）

效果：m 的边界向内收缩 8 像素 —— 恰好剥掉「轮廓 / 接触带」这一圈被掠射污染的像素。
代价：物体在图像上变"瘦" 8 px，但 TSDF 从 63 个视角融合，真实表面仍被大量近垂直观测覆盖；
     被剥掉的只是每一帧里不可信的那一圈，不是几何本身。
from scipy.ndimage import binary_erosion
m = binary_erosion(m, iterations=8)     # 23b_gs_to_mesh_v2.py，掩码生成之后、深度置零之前
为什么腐蚀能治「斗形」：斗形由接触带一圈被污染的深度观测投票造成。 腐蚀把这圈观测从每一帧里删掉，TSDF 里就只剩近垂直的干净观测—— 壁面恢复垂直。验证：重跑后 gs→gt 从 13.38 → 3.70 mm，Chamfer 7.87 → 3.00 mm。

7 · 最终方案与结果

7.1 v2 掩码的完整判据（全部几何量，无一涉及颜色）

  1. 有效性：depth ∈ (0.01, 0.8) 且 acc > 0.1（剔除空射线与哨兵深度）
  2. footprint：反投影到世界坐标，|x| < 0.083, |y| < 0.107（资产真实尺寸，比 v1 裁剪框收紧 8 mm）
  3. 高度窗口：0.033 < z < 0.080（桌面上方 3 mm 起步：桌面与物体底面同高，footprint 内有 ~8 mm 宽的桌面环带可见，靠 3 mm 余量剔除）
  4. 轮廓腐蚀：binary_erosion(m, iterations=8)（剔除掠射污染带）
  5. 颜色：用 GS 自渲染的 rgb 替代原始照片（单一 3D 一致模型，无逐帧曝光跳变）
世界坐标反投影（与 vol.integrate 同一套变换，保证一致）：
  p_cam = ( (u−cx)·d/fx , (v−cy)·d/fy , d )          OpenCV 相机系
  w2c   = inv(c2w @ FLIP)                             OpenGL→OpenCV 翻转，Lesson03 的老坑
  p_w   = (p_cam − t) @ R                             R = w2c[:3,:3], t = w2c[:3,3]

8 · 发白问题的诚实结论

换 GS 自渲染颜色只带来 +9% 的饱和度提升——远低于预期。复盘后判断数据端已到上限：

  • GS 是拟合原图训练的，原图里的高光它也会学进去（减轻但不根除）；
  • TSDF 的 RGB8 平均仍是简单加权，没有「哪帧更可信」的机制；
  • 剩余发白大概率在显示端：Isaac 的 PBR 材质 + 白光下，顶点色本来就偏淡。

验证方法：用 MeshLab 打开同一个 obj——若颜色明显更红，就别再动数据管线， 去 Isaac 里给材质启用 vertex color，或用 xatlas 展开 UV 把顶点色烘成贴图。

9 · 可复用经验

  1. 掩码判据要问语义，不是外观。「够不够彩」在红物体+白桌面上侥幸可用，换物体即崩。 几何判据（世界坐标 footprint + 高度窗）与物体颜色完全解耦。
  2. 先验证假设再写代码。本次最贵的弯路（斗形）源于凭直觉设计掩码； 后来一张 z × r 误差地图 5 分钟定位根因。距离分桶表应成为重建任务的标准诊断工具。
  3. 众数估计只对单峰分布可靠。场景里桌面不是最大表面时，几何先验反而更稳。
  4. acc ≠ 前景掩码。背景高斯同样不透明，acc≈1；它只是有效性信号。
  5. 掠射观测不可信。ED 在轮廓/接触带会混合前后两次命中——腐蚀掉这一圈， 比任何事后网格修补都便宜且诚实。
  6. 单边 Chamfer 会奖励「少重建」。报告时必须同时给 gs→gt、gt→gs 和 bbox。
  7. 指标变差不一定是坏事：迭代②把 v1 藏着的坏几何显形（7.87 mm）， 没有这次「变差」，就找不到斗形。

10 · 遗留限制

  • 底部 ~6 mm 缺失（bbox z 0.036 vs GT 0.042）：接触区被腐蚀 + 桌面余量剔除。 对凸包/碰撞影响极小，且比 v1 用破洞「假装」这块区域诚实。
  • 顶面小凹坑：GS 深度本身的空洞，属 RGB-only 管线上限。
  • gsplat JIT 缓存：重跑渲染前需保证与编译时一致的环境（TORCH_CUDA_ARCH_LIST 等）， 已固化为 scripts/fix_gsplat.bat（预编译）与 scripts/run_nerfstudio.bat（带环境运行）， 详见 Lesson02 第 4 节的缓存命中条件。
