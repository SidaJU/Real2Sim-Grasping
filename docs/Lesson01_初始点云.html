Lesson 01 · 初始点云：从「随机撒点」到「真值深度反投影」

项目：Real2Sim-Grasping（Isaac Sim 渲染 → 3DGS 重建 → 资产化 → 抓取）
本篇核心：3DGS 为什么需要初始点云、points3D.ply 到底是怎么算出来的、 以及我们怎么在没有 COLMAP 的情况下拿到比 COLMAP 好 68 倍的点云。
💬 本篇要回答的问题
「这个初始点云 points3D.ply 是怎么计算出来的？输入什么、算法是什么、输出什么？」

1. 一句话总结

3DGS 不是从零「长」出物体，而是从一批种子高斯球开始优化。 种子的初始位置决定了成败：给对了形状 → 精修即可；给错了（随机撒点）→ 永远收敛不成形。 我们用 Isaac Sim 的真值深度图反投影生成了 15 万点的种子，实测几何误差 < 0.3 mm。

2. 什么是初始点云

一批带颜色的 3D 点：(x, y, z, r, g, b)。

3DGS 启动时把每个点变成一个 3D 高斯球（位置 + 大小 + 颜色 + 透明度）， 之后靠自适应密度控制（缺细节处分裂、多余处剔除）把它打磨成实体表面。

✓ 有初始点云

雕塑家拿到已凿出粗胚的石料，只需精修表面细节。

✗ 无初始点云

拿到一堆散沙，要凭空捏出形状——沙子在手里只会越攥越散。

3. 【核心】points3D.ply 是怎么算出来的

反投影是拍照的逆过程。拍照是把 3D 世界压成 2D 像素（丢失深度）； 反投影则是拿着深度图，把每个 2D 像素推回它原本的 3D 位置。

3.1 输入什么（4 样）

rgb_XXXX.npyRGB 图 640×640 uint8 —— 只用来取点的颜色
depth_XXXX.npy真值深度图 640×640 float —— 核心输入，每像素一个 z
intrinsics.json相机内参：分辨率 + focal_mm + h_aperture_mm → 算出 fx, fy, cx, cy
相机位姿 c2w脚本按轨道公式算出来（不是读的）：3 个高度 × 36 个方位
→
points3D.ply150,000 行 ASCII：x y z r g b（世界坐标，米）
transforms.json真实内参 + ply_file_path 字段 + 99 帧位姿

采集脚本 06_capture_multiring.py 在 Isaac Sim 里绕物体转三圈 （低 0.05 m / 中 0.15 m / 高 0.30 m，每圈 36 个方位 = 108 帧）， 每一帧同时抓 RGB 和真值深度。这就是仿真相比真实世界的「特权」： 真实相机只能给你 RGB，深度得靠 COLMAP 去猜。

3.2 算法：反投影（一图看懂）

为什么公式这么简单？因为这是相似三角形。 图像平面上像素偏离主点 (u−cx)，物体在 z 处偏离光轴 X， 两者之比等于距离之比：(u−cx) / fx = X / z → 反解出 X = (u−cx)·z/fx。 焦距 fx 在这里就是「图像平面到光心的距离」，单位是像素。

3.3 完整算法步骤（99 张图逐张执行）

  1. 深度有效性过滤 —— isfinite(z) & (0.01 < z < 0.6)。 丢掉无效值和远处的墙，只留物体与近处桌面。
  2. 隔点采样 —— STRIDE = 2，每 2 个像素取 1 个 → 每张图 320×320 = 102,400 个候选点。
  3. 反投影到相机系 —— 套用图 1 的公式，得到 (X, Y, Z)。
  4. 坐标轴翻转 —— 公式用的是 OpenCV 约定（+Y 向下、+Z 向前）， 而我们的 c2w 是 OpenGL 约定（+Y 向上、−Z 向前），所以要 [X, −Y, −Z]。 这一步当初做反了，高斯全跑到相机背后，详见 §7 bug C。
  5. 变换到世界系 —— p_world = c2w @ p_cam。 每个点顺手带上该像素的颜色 rgb[v, u]。
  6. 半径裁剪 —— |xy| < 0.35 m，切掉远处桌面 （实测：不做这一步，远桌面点日后会变成满屏 floaters，见 Lesson 05）。
  7. 随机降采样 —— 99 张图累加后远超上限，随机抽到 MAX_PTS = 150,000。

3.6 让 nerfstudio 真正加载它

光有 ply 不够，必须在 transforms.json 里声明字段，否则 parser 仍然走随机初始化：

{
  "fl_x": 342.07,
  "fl_y": 342.07,
  "ply_file_path": "points3D.ply",   // ← 这一行是关键
  "frames": [ ... ]
}

nerfstudio 源码依据（nerfstudio_dataparser.py）： 有 ply_file_path → 加载 ply；否则找 colmap 目录；都没有 → 随机初始化。

点云坐标写成 USD 世界坐标即可，parser 会对点云和相机位姿施加同一套归一化。

5. 我们踩的坑：随机初始化

现象

第一次训练（36 张图）启动日志里出现：

Warning: load_3D_points set to true but no point cloud found.
splatfacto will use random point cloud initialization.

Viewer 里的结果：红色高斯碎片沿相机环形分布，物体位置是一团白色雾，完全不成形。

为什么会这样

splatfacto 默认从 COLMAP 解算出的 points3D.bin 加载种子。 我们跳过了 COLMAP（位姿是仿真真值），于是 nerfstudio 退化为在场景包围盒内随机撒点。

命运一：看得见的点

落在所有相机都看得到的地方 → 有梯度信号，慢慢长成物体（但密度远远不够）。

命运二：看不见的点

落在从任何相机都看不到的地方 → 永远没有梯度，永远停在原地， 成为你看到的「红色碎片环」。
结论：碎片不是训练没跑够，是初始化无解。加步数只会让雾更厚。 （更深入的机制——为什么看不见的点永远没有梯度、为什么位姿更错的 COLMAP 版反而能收敛——见 Lesson 03）

6. 顺带挖出的三个隐藏 bug

bug A：垂直内参 fy 错了 35%

相机 horizontalAperture=20.955、verticalAperture=15.29，比例不是 1:1。 我按 USD 语义算出 fy=468.8，但实测证明 Kit 渲染是各向同性的， verticalAperture 根本不参与成像。

判定方法（无歧义）：取画面下方同属桌面的两行像素反投影， 桌面是水平面，二者高度必须相等。

fy 假设三行桌面反投影高度桌面是否水平
fy = fx = 342.070.0253 / 0.0252 / 0.0252✅ spread 0.1 mm
fy = 468.78（v_aperture）0.0426 / 0.0517 / 0.0576❌ spread 15 mm，倾斜

诊断脚本：scripts/10_diag_depth.py（比脚本 09 的直方图法可靠得多）。

bug B：物体陷进桌面 2.5 cm

自检发现桌面在 z=0.025，而饼干盒底面在 z=0 —— 盒子埋进桌面 1/3 高度，那部分永远拍不到。 （真实场景物体放在桌面上，底部同样不可见，属物理真实；但这里是穿模，需要抬高物体修正。）

bug C：坐标系翻转方向搞反（曾让高斯全跑到相机背后）

早期版本对位姿做了 diag(1,−1,−1) 翻转，想把 USD 约定转成「OpenCV 约定」。 但 nerfstudio 的相机本来就是 OpenGL 约定（看向 −Z），和 USD 完全一致—— 这一转把每个相机都掉了个头，于是：

accumulation == 0  →  zero gradient  →  无 densification  →  模型冻结成一团半透明点云

正确做法：位姿保持 USD/OpenGL 原样，只在反投影那一步内部翻转 （[X, −Y, −Z]），见 §3.3 第 4 步。

7. 几何自检：用已知尺寸验证

点云是否正确，不能靠肉眼看，要和 YCB 官方尺寸比对：

expected  : 0.164 × 0.213 × 0.072 m   (cracker box)
measured  : 0.164 × 0.213  (x/y)        → worst x/y error: 0.000 m
measured  : z_top = 0.0723 m            → z error: 0.3 mm
VERDICT: OK - geometry is consistent

x/y 精确命中，z 方向也只差 0.3 mm → 内参、深度、位姿三者完全自洽。

脚本：scripts/08_verify_cloud.py（点云统计见 §3.5 实测表）。

9. 可复用的经验

  1. 3DGS 结果崩了先查初始化，不要急着加步数。碎片环 / 贴脸高斯 = 种子不对。
  2. 仿真数据的内参要从相机 prim 读，不要硬编码。 我们硬编码 10 mm，真实是 11.2 mm，直接导致第一版训飞。
  3. 几何自检必须有 ground truth。「看起来差不多」不算验证，拿已知尺寸量（本项目是 YCB 官方尺寸）。
  4. 判据要选无歧义的。判定 fy 时，直方图法给出矛盾结果； 换成「桌面必须水平」的几何判据后，0.1 mm vs 15 mm，结论一目了然。
  5. 先确认深度值的定义再套公式。沿光轴 vs 径向，差一个 cos θ，错了很难察觉。
  6. 别乱转坐标系。USD 和 nerfstudio 都是 OpenGL 约定，直接通用； 多此一举的 flip 会让高斯跑到相机背后，且症状极具迷惑性（不报错，只是训不动）。
