# Query-Guided 对照研究：D1／D2／D3 的异同与路线建议

- 整理日期：2026-11-17。
- 目的：回答“我们的三个研究内容是否接近 Query-Guided、路线是否合理、接下来应该集中做什么”。
- 对照方案：[论文骨架](论文骨架_跨表示资产一致性_QueryGuided模板.md)、[主框架](ICDE上榜论文抄作业_跨表示资产一致性框架.md)。
- 证据范围：论文 arXiv 扩展版 v2 的模型、定义、算法与相关章节，以及作者仓库的核心实现；源码提交为 `404b495`。
- 状态：**研究评估与实施建议，不是已实现成果，不确认全球首创、性能提升或录用。**本记录不改变现有骨架，不安装依赖、不运行实验、不修改 CoMe。

## 0. 核心结论

**总体思路接近，数据工程路线合理，但 D1／D2／D3 不是原论文三个贡献的一一对应。**

- **D1：角色部分相近，判定语义不同。**都关注最终输出，但我们的组合契约判定不是 MES 的直接替代实现。
- **D2：建议作为我们的主攻方向。**它研究版本和组合上下文变化后的证据有效性，不是 Query-Guided 的主要研究目标；原作也已有缓存和受影响结果更新，不能将这些基础能力冒称新增。
- **D3：与原文 MESReduce 最接近。**预算、成本、动态反馈和共享输入带来的收益已经存在；增加这些功能本身不构成新颖性。

**当前建议保持 D1＋D2，暂缓 D3。**这是基于范围和可执行性的取舍，不是因为 D2 最像原论文。若追求与原文算法结构最接近，D1＋D3 更接近；但没有必要为了“像一篇已发表论文”而扩大实现范围。

本轮的合理定位是：**受 Query-Guided 启发，研究面向交付请求的上下文敏感增量验证。**不是将数据库元组换成三维资产，就自动继承原论文的理论或创新。

### 1.2 问题与机制

论文的问题不是“如何重建三维物体”，而是：

> 数据已经被验证器标为正确或错误，但这些标签仍可能出错。标签错误会怎样影响最终查询结果？有限预算下，应该追加验证哪些输入？

核心流程为：**输入验证标签及其错误率 → 查询及 provenance（来源逻辑）→ 输出标签、MES 与 risky tuples → MESReduce 选择追加验证 → 更新结果。**

- **查询语义：**主要研究 SPJU（选择、投影、连接、并）查询，利用布尔来源表达式描述输入与输出的推导关系。
- **MES：**在使输出标签错误的可能世界中，取当前观测输入标签的最大似然。它不是直接计算所有错误世界的概率总和，也不能直接改名为资产失败概率。
- **risky tuples：**保持标签不变，仅降低某个输入标签的错误率，MES 反而可能升高。这是所定义指标的非单调性，不等于该元组或资产“特别容易坏”。
- **MESReduce：**优先关注高 MES 输出，结合来源结构、risky 判定和验证成本，选择输入集合追加验证，并更新结果；不是简单的逐项 `收益/成本` 排序。

原文的主要贡献是问题建模、指标及其性质、计算算法和引导验证的方法，**不只是把已有工具封装成统一入口**。

## 2. 与 D1／D2／D3 的逐项对应

| 维度 | Query-Guided | 我们的方案 | 判断 |
|---|---|---|---|
| 最终目标 | 提高查询输出标签的可靠性 | 判断资产在指定版本、上下文与用途下是否满足交付契约 | 同属面向下游用途的可靠性管理，但“正确”的定义不同 |
| D1：判定 | 从输入标签、错误率和来源表达式推导输出标签与 MES | 从实际事实、转换关系及有效证据，判定契约满足、违反或未决；冲突单报 | 功能角色接近，不能直接迁移模型、指标和保证 |
| D2：复用 | 预计算来源表达式、缓存部分验证结果，并更新受影响输出 | 将证据绑定产物、实际读取依赖、契约及组合上下文，管理失效与复用 | 是不同的主问题；不是“原作完全不缓存或不更新” |
| D3：规划 | MESReduce 按预算和成本追加验证，利用共享输入并接收反馈 | 选择检查、修复或暂缓；考虑共享准备成本与修复后的证据失效 | 与原作最接近；修复改变版本是需要另行研究的差异，不是自动成立的新颖性 |
| 状态变化 | 核心路径更新验证标签及错误率 | 除更新证据外，还可能修改资产、配置、引用，产生新版本 | 需要区分“认识改变”与“被检查对象改变” |
| 三态 | 原文已经有正确、错误、未知标签 | 契约为 verified、violated、undetermined，另有 evidence_conflict | 三态本身不是新贡献，不能因名称不同忽略语义差别 |

D1、D2、D3 是研究职责，不要求各自恰好实现为一个脚本，也不意味着必须写成三项论文创新。

## 4. 借鉴边界：保留什么，不能照搬什么

### 可以借鉴

- **最终目标导向：**根据本次交付要求反推需要哪些事实和证据，而非无差别检查所有产物。
- **复用现有底层工具：**不必发明新的重建网络或替换所有检查器，贡献可以在验证机制和数据管理层。
- **实际反馈闭环：**执行检查后更新状态，结果不足就继续检查或暂缓，不把一次检查通过当作全面正确。
- **质量与成本同时评价：**不能只追求更少调用，也不能忽略误放行、覆盖和总开销。

### 不能直接迁移

- **provenance 不等于运行 DAG：**前者具有输出推导语义；后者仅记录谁产生、引用或读取谁，必须另建实际转换关系。
- **MES 不等于 `U`：**我们的 `U` 是必要契约的未决比例，不是概率；`U=0` 仍可能全部违反。
- **来源相同不代表错误独立：**一个共享尺度错误可能影响多个 mesh、collider 和 USD 实例。
- **缓存有效不代表资产真实正确：**它只说明某条检查结论在声明条件下仍适用，不保证未检查的几何或动力学属性。
- **相似结构不转移理论保证：**不能直接把原论文的复杂度、单调性或可靠性结论写成本项目结果。

D1 仍须保留空解释集的独立冲突状态、求解超时的 unknown，以及证据等级和有效域。若事实已知、直接计算即可判定，不必为了形式感强制引入 SMT。

## 5. 建议主线：D1 做基础，D2 承担主要研究，D3 暂缓

### 5.1 固定一个核心问题

> **在资产版本与 USD 组合上下文持续变化时，针对具体交付契约，正确维护验证证据的适用性；与完整检查保持判定一致，并相较安全字段级缓存减少不必要的重检和总成本。**

这是立项目标，不是已经达到的结果。推荐 D2 主线是范围选择，不意味着它已经构成新算法。

### 5.2 D1：提供准确的任务定义与完整检查参照

第一版保留身份／来源、单位／有序变换、有效引用／上下文和碰撞配置四类契约。检查实际状态而非只读声明日志，区分未决、冲突和已证违反。

D1 首先需要证明判定正确，不预设“官方工具不会检查组合场景”。若相同规则通过现成工具即可得到同样判定，则应复用它们；仅增加规则或换成三态不能单列创新。

### 5.3 D2：必须补齐的三个技术答案

| 必须回答的问题 | 需要明确的设计与验证 |
|---|---|
| 如何获得完整依赖？ | 说明采用适配器声明、读取追踪还是两者结合；覆盖解析、结构、配置等相关依赖。黑盒依赖无法可靠记录时保守回退，不能继续复用 |
| 如何区分有效变化与无关变化？ | 不只比较曾读取文件的 hash；处理实际解析内容、有效字段、规则版本和组合结构的变化，同时避免无关修改导致全量失效 |
| 为什么胜过安全字段级缓存 B3？ | 指出具体机制差别及成本来源；B3 必须能访问相同上下文，不能故意漏掉父变换或 variant 依赖制造优势 |

**关键问题：为什么这不只是“给普通缓存 key 多加几个字段”？**如果答案只是记录版本、维护 DAG 和求失效闭包，当前贡献仍不足，需要继续查新和设计，而不是先把全部模块实现出来。

可能的研究价值应落到依赖获取、适用性判定、上下文间合法复用或维护开销中的具体增量；本轮尚未选定、实现或证明其中任何一种新机制。

### 5.4 D3：按工作负载决定，不为凑贡献而做

先测实际检查成本。如果主要是便宜的元数据读取，或者普通固定顺序、成本加权覆盖已足够，则不开发专用规划器。

若后续确有昂贵互补检查和修复，可以研究共享准备成本、修复创建新版本、旧证据失效后追加复核等问题；但这些也需对照通用规划和增量计算，不能因原论文的核心路径未处理资产修复，就直接称为空白。

### 5.5 接入 CoMe 的定位

建议从外围接入：**CoMe 重建／提取 → mesh、collider、USD 组装 → 契约验证与证据管理 → 必要修复和复核 → 交付。**

这可以研究流程可靠性，但不自动提升 CoMe 的收敛率或几何精度。D2 本身不修复坏资产；提高合格交付数量还需要有效修复，不能靠拒绝所有困难资产制造“高成功率”。

## 6. 最小验证范围与强基线

### 6.1 先覆盖这些变化，而不是先堆大系统

| 案例 | 应验证的行为 |
|---|---|
| 源文件不变，但 variant 切换导致实际引用变化 | 相关旧证据必须失效，不只看文件 hash |
| 父变换或碰撞配置改变 | 依赖这些状态的结论重检；不相关证据不应一律丢弃 |
| 修改被更强 layer 覆盖的弱层字段，最终有效值未变 | 在已验证依赖完整且结论不依赖该弱层事实的条件下，判断是否可以合法复用 |
| 修改不被当前契约读取的显示属性 | 不应触发无关几何或身份检查；涉及材质物理属性的修改不能混同为无害 |
| 检查器／契约版本改变或发现隐藏依赖 | 重新核查适用条件，无法确认时回退完整检查 |
| 修复产生新资产版本 | 更新依赖、失效相关证据并复核，不能将修复前结果直接用于新版本 |

这些是正确性与成本的测试义务，**不是已经证明 B3 无法处理的反例**。必须加入自然变更记录，受控注入不能替代真实需求。

### 6.2 对照对象

| 基线 | 目的 |
|---|---|
| 官方验证工具及适用规则／Profile | 明确现成功能边界，不把它们弱化成格式检查 |
| B1：相同契约的完整检查 | 验证没有为了加速遗漏检查或改变判定口径 |
| B2：文件 hash 缓存／保守依赖失效 | 排除普通缓存本身带来的收益，不作为唯一主要对手 |
| **B3：安全字段级依赖缓存** | **D2 的主要强基线**；拥有相同上下文和相关依赖信息 |
| B4：固定顺序、成本加权覆盖等 | 仅在实现 D3 时评估其额外规划价值 |

Query-Guided 是思想来源和相关工作，**不是 D2 天然可直接比较的端到端基线**。只有能正确映射标签、错误率、来源语义与任务目标的子问题，才考虑适配 MESReduce；不能随意构造概率后用另一种指标宣称胜过它。

### 6.3 评价与继续条件

- 与同契约全检比较状态差异，并用独立审计识别双方共同犯错；测试集上零差异不等于对全部场景的普遍保证。
- 统计证据误复用、重检次数、机器时间、墙钟时间、峰值资源，以及适用时的人工活跃时间。
- 成本包含依赖追踪、指纹计算、解析、索引维护、失败动作和修复复核；不能只报告省下的检查时间。
- 冷启动、热请求、低复用、大范围修改、不同上下文和自然／注入故障分别报告；同一对象变体不能当独立对象放大统计显著性。
- 若讨论交付成功率，固定同一批输入，报告独立核验合格交付数／全部任务数，同时报告错误放行、拒绝／暂缓和无标签结果。

**继续条件：**有真实重复检查需求；D2 有明确机制差异；判定能力不因复用受损；相对安全 B3 的净收益可重复观察。

**收窄或停止论文创新主张的条件：**收益只来自新增规则或普通缓存；依赖不全导致误复用；追踪开销抵消节省；效果仅靠弱基线或注入案例成立。工具仍可有工程价值，但不能据此声称新算法。

## 7. 对 ICDE 定位的结论

契约、证据生命周期和增量验证与数据质量、信息集成及工作流管理相关，保留 CoMe 为后端并不是问题。**真正的贡献必须落在数据管理机制或非平凡的工业系统／应用改进，而非三维题材本身。**

与 Query-Guided 思路相近，只能支持这类问题具有数据工程意义，不能证明本方案已满足投稿标准。是否形成 Industry 稿件，仍取决于实际需求、非学术机构作者资格、机制差异和可信实验；官方要求以 [ICDE 2027 Industry CFP](https://icde2027.github.io/cf-industry-track.html) 为准。

**下一步优先补齐 D2 的算法设计与 B3 对照，不继续增加模块，也不把 D1／D2／D3 三个名字直接当作三项创新。**
