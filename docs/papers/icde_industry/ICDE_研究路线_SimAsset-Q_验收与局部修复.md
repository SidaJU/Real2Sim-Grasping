## 1. 选题结论与研究问题

### 1.1 为什么选择 Real2Sim-Grasping

在当前约束下，优先复用 `Real2Sim-Grasping`，不继续扩展 RSSM 或 RL：

- 已有图像、相机、深度、高斯、网格和 USD 的处理链，可以直接研究异构数据转换。
- 已有尺度还原、坐标转换、掩码、网格缺失和资产引用等具体问题，不必假设一个尚未观察到的瓶颈。
- 许多诊断和修复可复用冻结模型及其导出结果，不依赖多组训练是否收敛。
- 应用收益可以落到资产验收、返工成本和仿真可用性，而不只是模型损失下降。

这是基于现有证据与开发成本的可行性判断，不是对两个项目录用概率的量化排名。两个项目目前都没有充分的工业使用证据。

### 1.2 一句话研究问题

**如何在三维重建资产投入仿真之前，识别跨格式、跨阶段的数据错误，定位受影响的产物，并以较低的总成本完成验收和必要修复？**

主流程：

**RGB／相机／初始化数据 → 3DGS → 深度／颜色 → mesh → 碰撞表示／USD → 仿真验收。**

研究对象是这条数据处理链的可靠性和成本，不是新的 3DGS 表示、抓取策略或物理引擎。

### 1.3 三个可检验的问题

| 编号 | 问题 | 所需证据 |
|---|---|---|
| RQ1 | 独立文件都能读取时，跨表示不一致是否仍会导致资产不可用？ | 可重放的自然故障、明确的上下游关系、独立质量标签 |
| RQ2 | 分级验收能否以较低检查成本识别这些问题，而不过度拒绝好资产？ | 与固定检查的检出率、误报率、漏放风险和交付率对照 |
| RQ3 | 错误定位和针对性修复是否优于固定检查加普通依赖缓存？ | 相同信息、算子和缓存条件下的修复成功率、总耗时及人工操作成本 |

没有证据表明高面数碰撞查询是当前主要瓶颈，因此本周不以“新碰撞网格简化算法”为主线。

## 4. 最小系统设计

### 4.1 模块 A：资产身份与跨阶段质量规则

每个产物有独立版本和可追溯输入，不再只靠对象名称、目录或 `latest` 指针识别。

建议记录：

| 字段组 | 最少内容 |
|---|---|
| 身份 | 对象 ID、产物类型、版本、内容指纹、生成时间 |
| 来源 | 数据来源、许可、观测 ID、GT／估计值的使用位置 |
| 几何约定 | 长度单位、坐标轴约定、相机变换方向、深度含义、归一化变换 |
| 依赖 | 上游产物 ID、代码版本、相关参数、模型版本 |
| 质量证据 | 检查项、适用范围、阈值版本、检查结果与耗时 |
| 交付 | mesh／碰撞体／USD 的绑定关系、仿真加载的实际版本 |

跨阶段规则至少覆盖：

- RGB、深度和相机是否来自同一观测，数量一致不代表配对正确。
- 相机矩阵和深度约定是否符合所用导出器；不能对所有来源盲目套同一个轴翻转。
- 归一化深度、网格和 USD 是否使用同一尺度及变换。
- USD 引用的资产是否与本次重建、检查及评测的产物一致。
- 视觉网格与实际碰撞表示的坐标和尺寸是否一致。

缺少可靠米制尺度依据时应标为证据不足，而不是按类别猜尺寸并声称恢复真实尺度。

### 4.2 模块 B：分级验收

先执行便宜检查，再为有必要的资产执行昂贵检查。

| 层级 | 检查内容 | 不可夸大的结论 |
|---|---|---|
| L0 元数据与格式 | 文件身份、观测配对、单位、变换、引用版本、空或退化几何 | 通过不代表几何真实 |
| L1 观测与几何一致性 | 深度回投影、轮廓／覆盖、支撑或接触区域证据、mesh 与碰撞表示差异 | 多视角一致可能共享系统误差；不能等同真实几何保证 |
| L2 仿真验收 | 导入、静置、碰撞检查、有限固定动作回放 | 有限试验通过不代表全部工况或真机安全 |

输出三个状态：**通过当前用途验收／需要修复或追加检查／证据不足或不可修复而拒绝**。

检查阈值只在开发与校准对象上设置，测试前冻结。检查等级和用途必须随产物保存；只完成 L0 的资产不能标注为“抓取验证通过”。

如果覆盖检查从最终 mesh 出发，会漏掉被掩码删光的区域。因此必须同时检查过滤前观测、掩码和指定任务区域。参考表面可以离线评测，但不应偷偷进入无 GT 的在线判断。

### 4.3 模块 C：错误定位与最小必要重算

将检查失败映射到有明确前置条件的有限修复算子，不引入 LLM 自动猜测或开放式修复。

| 问题 | 允许的处理 | 重算边界 |
|---|---|---|
| 导出时遗漏已知尺度／全局坐标变换 | 根据可信元数据重新变换和导出 | 更新相关几何及 USD，复核碰撞配置 |
| 仅后处理掩码／TSDF 参数有问题 | 使用冻结 GS 已有的兼容深度重新过滤和融合 | 重建 mesh 及下游；不声称改变体素尺寸后可无条件复用旧 TSDF |
| USD 引用了旧版、错误对象或 GT 产物 | 重新绑定已验证的目标资产 | 重做导入和下游验收 |
| 坐标或相机错误已参与训练 | 修正输入并使训练及后续产物失效 | 不能只改导出变换掩盖错误；预算不足则拒绝并报告 |
| 缺乏足够观测、未知真实尺度或材料 | 要求补充数据／校准，或拒绝 | 不用猜测补洞、尺寸或摩擦并宣称正确 |

最小决策流程：

1. 收集失败规则及其上下游依赖。
2. 筛选前置条件满足的修复算子。
3. 根据历史阶段耗时估计新增处理和复核成本。
4. 选择低成本、可解释的候选，执行后复核。
5. 超过预算或证据仍不足则拒绝，保存原因。

所有策略都应拥有相同的普通依赖缓存。拟研究的是跨表示错误定位与验收决策的增量价值，而不是“我们有缓存，基线没有”。

原始文件只读保存；修复产生新版本，不覆盖历史证据。

## 5. 数据与实验协议

### 5.1 数据分阶段准备

- 第一阶段：3–5 个不同物体，验证环境、成本瓶颈和故障是否可重放。
- 初始完整实验预算：8–12 个独立物体，按首日实际吞吐调整，覆盖盒状、圆柱、凹形和薄结构。
- 对象级划分开发／校准／测试；同一物体的视角和错误变体不能跨划分制造独立样本。
- 每个物体固定训练一次，各系统策略共享该冻结模型。不要将重建随机性混入修复策略对比。
- 数据许可未核实前不再分发原始资产或权重。

这个数量是起步预算，不是投稿充分条件或 ICDE 官方门槛。少量对象的结论必须收窄，不声称对所有物体普适。

### 5.2 两种故障来源分开统计

**自然故障：**来自实际管线运行和已有记录，保存输入、配置、症状、产物和人工判定依据。

**受控注入：**帧／相机错配、遗漏尺度转换、错误坐标声明、过期引用等，用于验证检查覆盖和修复边界。注入位置与强度预先固定，不能只挑本方法容易处理的问题。

人工注入不能替代工业使用证据。检测到人为破坏也不能单独证明新颖性；简单格式验证、固定规则可能已经足够，必须公平比较。

### 5.3 参考答案与 GT 隔离

- 使用原始合成资产或独立测量参考建立几何与用途标签，注明参考的有效区域。
- 在线规则只使用明确允许的输入元数据、观测和固定用途要求。
- 若源数据有 GT 位姿、GT 深度初始化、物体尺寸等特权信息，所有相关策略采用同样条件并公开说明。
- 测试参考几何、测试抓取成败不能用于在线挑修复参数或选最优产物。
- 对于完全未观察到的表面，只能表达未知；不通过删除该区域的评价来提高结果。

### 5.4 仿真验收范围

所有对象尽量完成导入、静置和碰撞检查；抓取仅选现有控制器可适配的少数对象作为应用验证。

- 先确认实际加载的是 GS mesh，而不是 `gt_mesh.obj`。
- 可从 2–3 个适配侧抓的物体、每个 20 个配对初始条件起步；试验次数是预算建议，不是统计保证。
- GT 参考、未经治理的重建资产、治理后资产使用相同控制器、初态、质量、摩擦和成功判据。
- 质量与摩擦统一指定，不声称由 3DGS 恢复了真实物理参数。
- 抓取成功判据在开发阶段冻结；报告分母、失败类型和区间，不只展示成功视频。
- 不让本周工作演变成面向所有形状的新抓取策略开发。

## 6. 基线与消融

| 组别 | 配置 | 比较目的 |
|---|---|---|
| B0 原有流程 | 当前脚本及明确记录的人工步骤 | 建立实际操作与返工成本参考；不刻意禁用原本已有优化 |
| B1 固定验收＋普通缓存 | 常规格式／几何检查、固定顺序、标准依赖失效与缓存复用 | 排除收益仅来自补检查或加缓存 |
| B2 通用修复搜索 | 与本方法相同的修复算子和检查接口，在同预算下按固定顺序或网格尝试 | 排除收益只是增加了可选参数 |
| Q 本方法 | 跨表示规则、分级验收、失败定位和成本感知修复 | 验证拟新增机制的增量价值 |

各组共享输入信息、后端、候选算子、缓存容量、硬件、预算及最终验收要求；不同检测能力需要明确列出。

最少做两项消融：

1. 去掉跨表示绑定／定位，只保留文件内检查。
2. 保留相同规则与缓存，改为固定检查和固定修复顺序。

若涉及一般网格有效性检查，应复用并与现成库或 USD 检查能力比较，不把“检查空网格”作为新的技术贡献。

本周不宣称几何重建 SOTA。若后续宣称精度优于 CoMe、TopoSurfel 等，需另外运行这些方法的官方流程、统一先验和协议，而不是拿作者表格中的数值直接拼对比。

## 7. 指标、计时与图表

### 7.1 指标口径

| 指标 | 统计方式 |
|---|---|
| 初始坏资产检出率 | 在修复前，对独立标注为不合格的输入有多少被正确拦截 |
| 好资产误报／误拒 | 独立标注为合格的输入被错误标记或最终拒绝的比例，分别报告 |
| 最终漏放风险 | 放行产物中，经独立评价仍不达标的比例；无放行时标为不适用，不写成零风险 |
| 交付率 | 最终放行数量／全部请求数，避免靠拒绝所有资产获得漂亮风险指标 |
| 修复成功率 | 预先界定为可修复的故障中，最终达标的比例；不可修复故障另列 |
| 总准备／修复成本 | 检查、执行、缓存访问、失败重试、导入与复核的总耗时及峰值资源 |
| 人工成本 | 实际人工活跃操作分钟数、干预次数；不把无人值守等待算作人工节省 |
| 应用效果 | 导入率、静置／碰撞验收、配对抓取结果及几何误差 |

### 7.2 公平计时

- 首次准备成本和已有兼容产物下的增量修复成本分开报告。
- 若共享冻结重建模型，可以隔离比较后处理成本，但仍列出共同训练成本；不能把共同成本说成不存在。
- 缓存冷启动与热启动分别报告，计入检查索引和元数据构建开销。
- 记录 GPU／CPU 型号、显存、内存、并行度、软件版本与输入规模。
- 同一环境重复运行，报告中位数或均值及波动；必要时按物体聚合，不能把大量相关帧当作独立样本夸大显著性。

### 7.3 论文最少四张图／表

1. **系统图**：资产流、检查层级、定位与修复路径。
2. **失败案例图**：同一资产修复前后及独立证据；包括系统无法修复的例子。
3. **成本—质量图**：漏放风险／交付率与总成本的权衡，不只比较运行秒数。
4. **对照及消融表**：各组检出、误拒、修复成本、人工操作和应用结果。

所有数值由结构化运行记录生成，不手填想要的改善百分比。

## 9. 继续与停止条件

### 可以继续投入的信号

- 跨表示错误在实际管线中可复现，确实造成资产或实验不可用。
- 新规则对独立对象有增量检出能力，而不是只识别人为制造的明显格式错误。
- 在近似相同的最终验收风险与交付率下，本方法比 B1／B2 有稳定的成本收益。
- 收益大于新增检查与维护开销，能被真实使用者理解和复用。

### 必须收窄或停止的情况

- 现有文件检查和普通 DAG 缓存已经解决全部问题。
- 需要为每个测试物体手工调阈值才能有效。
- 依靠测试 GT 或事后挑选最优参数才能达到结果。
- 通过拒绝大多数资产才获得低漏放率。
- 加工开销很小，所谓节省不足以抵消检查成本。
- 只有单次成功视频，没有重复结果与独立参考。
- 没有合格产业作者，或无法提供与论文主张相匹配的实际应用证据。

如果只能证明诊断有用而不能自动可靠修复，应将论文收窄为“验收与诊断”，不能保留“自动质量保证交付”的强结论。

## 10. 硬件与执行边界

- A100 用于兼容的 3DGS 训练、深度导出或批量计算；具体软件兼容性在 D1 实测，不预设环境已经可用。
- Isaac Sim 使用原来已验证的 RTX 工作站。NVIDIA 官方明确[无 RT Cores 的 A100／H100 不受支持](https://docs.isaacsim.omniverse.nvidia.com/latest/installation/requirements.html)。A100 不能替代 RTX 渲染环境。
- 原工作站配置低于最新推荐规格时，只按已验证的小场景能力安排，不推断能运行所有新基准。
- 不覆盖已有成功环境、脚本或原始资产；新配置和实验产物隔离存放。
- 不在这一周迁移多个仿真器、扩展 DUSt3R／EcoSplat、开发新 CUDA 或新增 RL。

## 11. 六页候选论文的结构

下面是内容预算，不是排版保证；参考文献另计。

| 部分 | 建议篇幅 | 必须回答 |
|---|---:|---|
| 摘要、引言与应用问题 | 约 1 页 | 谁需要此系统，哪类资产错误代价高，现有方法为什么不足？ |
| 数据模型与系统设计 | 约 1 页 | 资产、表示、依赖、质量证据如何组织？ |
| 验收、定位与修复机制 | 约 1.5 页 | 超出固定规则和普通缓存的部分是什么？ |
| 实验与应用案例 | 约 2 页 | 质量、成本、强基线、消融和实际使用证据是否支持贡献？ |
| 相关工作、局限与结论 | 约 0.5 页 | 适用范围、不解决的问题，以及与已有系统的区别是什么？ |

可以写：在明确输入和用途下，系统发现哪些跨表示错误、减少了哪些重复加工、对独立对象获得什么实测收益。

不能写：没有真机实验却声称 sim-to-real 成功；没有部署却声称生产应用；把 GT 辅助结果称为 RGB-only；把单对象 3 mm 历史结果归因于本方案。

使用 AI 辅助代码、实验或论文内容时，按[ICDE AI 使用政策](https://icde2027.github.io/cf-research-papers.html)如实披露，并由作者承担核验责任。不双投，不伪造署名、数据、引用和实验。
