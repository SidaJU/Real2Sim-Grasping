## 4. 选哪一篇抄：裁决

**选 `Query-Guided Analysis and Mitigation of Data Verification Errors`（ICDE 2026）作为主模板，DataSculpt 作为次级机制补充。**

### 为什么是它（逐条）

1. **问题结构同构**：它的核心叙事是"已有的验证工具会出错 → 错误沿查询传播 → 量化最坏影响 → 引导有限验证资源"，你的核心叙事是"已有的检查/人工验收会出错 → 错误沿资产依赖图传播 → 量化交付风险 → 引导有限检查/修复资源"。**这是同一篇论文的骨架，只是数据域从元组换成三维资产产物。**
2. **它明确"complement，不 replace"**（原文："our framework is not intended to replace existing systems but to guide and enhance their use"）——你也不该替换 CoMe/现有管线，而是在之上加一致性层。这个定位审稿人最容易接受。
3. **它的实验设计可以直接照搬**：三种场景（real-labels / worst-case / average-case）+ 四个 baseline（Random / Formula-Count Greedy / Occurrences-Count Greedy / Probability Greedy）+ F1-vs-cost 曲线 + runtime。你的 B0/B1/B2/Q 对照和成本-质量曲线就是这个模板。
4. **它有形式化武器**：provenance k-DNF、MES 最坏情况指标、risky tuples 反直觉发现——这是你目前最缺的"把直觉变成论文"的东西，照着它建你的资产依赖图 + worst-case 交付风险指标。

### 为什么 DataSculpt 排第二

它把数据组织形式化成 MOCO（多目标组合优化：relevance/integrity/homogeneity/cost），方法骨架是 coarse-to-fine（先聚类、再贪心搜索）。你可以用它来支撑"检查计划选择是会意多目标优化"这一条，但它的 LLM 训练场景离你远，只能借机制不能借叙事。

### 为什么不选其它

- TAMIS/RAMSeS：给"工业系统论文怎么写"和"自适应选择"的局部思路，但问题结构不如 Query-Guided 同构。
- FlowFill/CDMap/mAP：方向对但无开放 PDF，无法读原文抄细节；且它们的"补值/质量增强/检测"是单点问题，没有"传播 + 成本决策"这条主线。

## 5. 具体借鉴清单（把 Query-Guided 翻译成你的论文）

| Query-Guided 的元素（原文有据） | 你的对应（待写/待做） |
|---|---|
| Provenance：k-DNF 表达输入→输出依赖 | 资产依赖图：节点=产物，边=生成/引用关系，标签=检查状态+置信度 |
| MES：worst-case 错误，独立于数据分布 | 资产 worst-case 交付风险：当前证据下最坏可能违反哪条跨表示规则 |
| Risky tuples：减少某输入不确定性反而增加输出不确定性 | 关键洞察候选：某些"看起来通过"的检查（USD 可加载/mesh 非空）反而掩盖跨表示不一致——把检查预算指向它们 |
| MESReduce：引导外部 verifier 选下一步 | 分级验收：L0 全跑 → L1 高风险才跑 → L2 极高风险才仿真回放 |
| 不替换已有工具 | 不替换 CoMe/现有流程，在其交付物之上加一致性层 |
| 3 场景 + 4 baseline + F1-vs-cost 曲线 | 真实故障/最坏注入/平均注入 + B0/B1/B2/Q + 交付可靠性-vs-成本曲线 |
| Prototype system + real & synthetic data | 你的原型系统 + 自然踩坑记录 + 受控注入故障 |
| 严格形式化（布尔公式、k-DNF、ILP/PTIME 算法） | 你必须写出：依赖图形式化、错误传播规则、worst-case 指标定义、选择算法目标函数 |

**最重要的一句话**：抄它的骨架（验证错误传播 → 量化 → 引导有限验证），不要抄它的具体技术（k-DNF/ILP 不适合你的三维资产）；你的贡献是**把这套骨架第一次用在跨表示三维资产上**。
