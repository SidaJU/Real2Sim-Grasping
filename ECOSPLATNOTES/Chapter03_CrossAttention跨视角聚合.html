Chapter 03 · Cross-Attention（跨视角聚合）

承接 Chapter 02：Encoder 里每个视角各自独立做 Self-Attention，视角之间还没说话。
本章讲它们怎么开始说话 —— 全程先用简化例子讲清原理，最后才回到 EcoSplat 的真实维度。
真实目标：q 长 257、k/v 长 514、12 头 × 64 维、Decoder 12 层。
一句话

Self-Attention：Q、K、V 全都来自同一个序列（自己跟自己比）。
Cross-Attention：Q 来自序列 A，K 和 V 来自序列 B（拿 A 的问题，去 B 的信息里查）。
公式一模一样，只是「喂进去的东西」不一样。

先对齐术语：A、B 到底是什么？（它们都是你熟悉的 X）

你在 Ch.02 已经掌握的 self-attention：

Q = X · W_q
K = X · W_k      ← 三行里的 X 是【同一个】序列
V = X · W_v

cross-attention 只改了一件事：把 K、V 公式里的 X 换成另一个序列。

Q = A · W_q      ← A 扮演的就是上面那个 X 的角色
K = B · W_k      ← 这里不再是 A，换成 B 了
V = B · W_v      ← 同上

所以 A 和 B 都是 token 序列，和 X 是同一种东西（都是「一堆 4 维向量」）， 区别仅在于被放进哪条公式。

本书/论文里的叫法它实际是什么在公式里的位置EcoSplat 里对应
query / query 侧 / Q 的输入序列 AQ = A·W_q本视角的 token
context / memory / K,V 的输入序列 BK = B·W_k、V = B·W_v其他视角拼起来的 token

叫它 context 是因为它扮演「供你查询的资料库」这个角色（中文就是上下文/记忆）—— 本质上它就是另一个 X，没有别的玄机。

同理，源码 DecoderBlock.forward(self, x, y, ...) 里： x = 本视角序列 = 本例的 A；y = 其他视角拼起来的序列 = 本例的 B。

【勘误 ①】层级搞错了：一个 token ≠ 一个视角

这是最容易混淆的一点，先说清楚：

❌ 错：   我 = 视角 A      爱 = 视角 B      中国 = 视角 C
         （把「token」和「视角」当成了同一层的东西）

✅ 对：   视角 A（第 1 张图） = [我, 爱, 中国]          一整串 token
         视角 B（第 2 张图） = [我, 爱, 中国, 的]      另一整串 token

「我 / 爱 / 中国」是同一张图内部的三个 patch，它们合起来才构成一个 X。 视角比 X 高一层：一个视角 → 一张完整图 → patchify 出一整串 token。

层级句子类比EcoSplat 里对应
一个序列一「句话」一个视角的全部 patch
序列里的元素一个「词」一个 patch（token）
Self-Attention句内：这个词跟句里其他词的关系每个视角自己内部，patch 之间互相看
Cross-Attention句间：翻译时这个词该对齐源句哪个词本视角的 patch 去别的视角里找对应

重说一遍 §1 那个例子：
A = 「我 爱 中国」这一整句（3 个 token），B = 换个角度拍的同一场景（4 个 token，多出一块背景）。
所以 §1 里标的「左耳 / 鼻子 / 尾巴」表示的是同一个物体在两张图里互相对应的 patch， 不是两种不相干的东西 —— 这个标注容易误导，已在此勘误。

顺带回答：为什么不干脆把 A、B 拼成一个大 X 做 self-attention？
  1. 输出形状不对：拼成 v×N 的大序列，出来还是 v×N 混在一起；下游 DPT head 需要 每个视角各自的 (b, v, l, c) 特征图来还原每个视角的输出。
  2. 角色要分清：cross-attention 明确区分「我是谁（Q）」和「我查到了什么（K/V）」；拼起来就分不清了。
  3. 计算量：self-attention 是 O((vN)²)，cross-attention 是 O(N × (v−1)N)。 v=3 时前者 9N²，后者 2N²。

1. 先用最简例子：两个视角，故意不等长

为了让「两个序列」这件事一眼看出来，故意让它们长度不同：

【序列 A】—— 用来算 Q 的那个输入（3 个 token，每个 4 维）
            它扮演的角色，就是 self-attention 里 "Q = X · W_q" 的那个 X

  a1 = [1, 0, 0, 0]     ← 猫的左耳
  a2 = [0, 1, 0, 0]     ← 猫的鼻子
  a3 = [0, 0, 1, 0]     ← 猫的尾巴
                                    A 形状 (3, 4)

【序列 B】—— 用来算 K 和 V 的那个输入（4 个 token，每个 4 维）
            它扮演的角色，就是 "K = X · W_k"、"V = X · W_v" 里的那个 X，只是换成了 B
            同一个物体，另一个角度拍的

  b1 = [1, 0, 0, 0]
  b2 = [0, 1, 0, 0]
  b3 = [0, 0, 1, 0]
  b4 = [0, 0, 0, 1]     ← B 多出来的一块背景
                                    B 形状 (4, 4)

【三套权重】注意：cross-attention 里 Q、K、V 各有【自己】的投影矩阵

      [ 4  1  0  0 ]          [ 1  0  0  0 ]          [ 2  0  0  0 ]
W_q = [ 1  4  0  0 ]    W_k = [ 0  1  0  0 ] = I      W_v = [ 0  2  0  0 ] = 2·I
      [ 0  1  4  2 ]          [ 0  0  1  0 ]          [ 0  0  2  0 ]
      [ 0  0  0  1 ]          [ 0  0  0  1 ]          [ 0  0  0  2 ]

  缩放：除以 √4 = 2，即 scores = Q·Kᵀ × 0.5   （和 Ch.02 完全一样的规则）

1.1 五步手算

【第 1 步】Q 只从 A 来      Q = A·W_q  （3×4）

      [ 4  1  0  0 ]     ← q1（左耳在问：谁跟我像？）
  Q = [ 1  4  0  0 ]     ← q2（鼻子）
      [ 0  1  4  2 ]     ← q3（尾巴）

【第 2 步】K、V 只从 B 来   K = B·W_k = B（4×4）    V = B·W_v = 2B（4×4）

      [ 1  0  0  0 ]          [ 2  0  0  0 ]
      [ 0  1  0  0 ]          [ 0  2  0  0 ]
  K = [ 0  0  1  0 ]      V = [ 0  0  2  0 ]
      [ 0  0  0  1 ]          [ 0  0  0  2 ]

【第 3 步】scores = Q·Kᵀ × 0.5    形状 (3, 4) —— 注意【不是方阵】

          [ 2.000  0.500  0.000  0.000 ]    ← a1 对 b1/b2/b3/b4 的分数
  scores = [ 0.500  2.000  0.000  0.000 ]    ← a2
          [ 0.000  0.500  2.000  1.000 ]    ← a3

  逐项验一下第一格：scores[0][0] = [4,1,0,0]·[1,0,0,0] × 0.5 = 4 × 0.5 = 2.0 ✓
  ⚠️ 这里是 3 行 4 列：行数跟着 A（query），列数跟着 B（context）。

【第 4 步】softmax（逐行归一，每行加起来 = 1）

          [ 0.6694  0.1494  0.0906  0.0906 ]    a1：66.9% 看 b1
  attn =  [ 0.1494  0.6694  0.0906  0.0906 ]    a2：66.9% 看 b2
          [ 0.0784  0.1293  0.5793  0.2131 ]    a3：57.9% 看 b3、21.3% 看 b4

【第 5 步】out = attn · V    形状 (3, 4)

  out[0] = 0.6694·[2,0,0,0] + 0.1494·[0,2,0,0] + 0.0906·[0,0,2,0] + 0.0906·[0,0,0,2]
         = [1.339, 0.299, 0.181, 0.181]

         = [0.299, 1.339, 0.181, 0.181]
  out[2] = 0.0784·[2,0,0,0] + 0.1293·[0,2,0,0] + 0.5793·[0,0,2,0] + 0.2131·[0,0,0,2]

                    [ 1.339  0.299  0.181  0.181 ]
  out (最终输出) =  [ 0.299  1.339  0.181  0.181 ]      形状 (3, 4)
                    [ 0.157  0.259  1.159  0.426 ]
三件立刻能看出来的事
  1. 输出的行数 = query 的长度（3），不是 context 的长度（4）。 「查完就走」，拿回来的信息被压缩进 A 自己的 3 个 token 里。
  2. scores 不是方阵（3×4）。Self-Attention 里 scores 一定是 N×N 方阵， 因为自己和自己比；cross-attention 没有这个约束 —— 这是两者最直观的形状区别。
  3. Q、K、V 用的是三套不同的权重（W_q / W_k / W_v）。 Self-Attention 里三者也各有一套，但因为输入相同，实现上常常合成一个大矩阵； cross-attention 输入不同，必须分开写（见 §4 源码）。
  4. ⚠️ 这个手算例子是「单头」的：4 维 = 1 个头 × 4，所以除以 √4。 真实的 cross-attention 是 12 头 × 64 维 = 768， 分头方式和 Ch.02 §4 讲的完全一样 —— 把输出维度切成 12 段，每段 64 维各自算 scores、各自 softmax， 最后 concat + proj。这里只是为了能手算，把分头那一步省掉了。

3. 为什么这就叫「跨视角聚合」

回头读第 4 步那张注意力表：

a1（左耳）→ 66.9% 看 b1
a2（鼻子）→ 66.9% 看 b2
a3（尾巴）→ 57.9% 看 b3、21.3% 看 b4（B 里那块背景）

每个 token 都在 B 里找到了跟自己最像的那个位置。如果 B 是同一物体从另一个角度拍的照片， 那么「谁跟谁分数高」就隐式地表达了两个视角之间的对应关系 —— 传统方法里要靠极线几何 + 特征匹配去算的东西，这里由网络自己在数据里学出来。

聚合的结果（第 5 步）：A 的每个 token 都掺进了 B 的信息。 A 的 token 从此不再是「只看过自己这张图」，而是「看过别人之后更新过的自己」。

一个容易搞混的点

Cross-attention 不改变序列长度：进来 3 个 token，出去还是 3 个 token。 变的是每个 token 里装的东西（从「只有自己的信息」变成「融合了 B 的信息」）。 长度要变，得靠别的操作（比如拼接，见下一节）。

4. 多个「提供 K/V 的视角」怎么喂进去：拼接

上面只有一个 B。真实情况里，A 要同时参考好几个其他视角。做法很朴素：把它们首尾接成一条长序列， 拼出来的那条长序列就是源码里叫 context（变量名 y）的东西 —— 它仍然是「用来算 K/V 的那个 X」，只是变长了。

简化例子：3 个视角，每个 4 个 token

  视角 0 的 context = [视角1 的 4 个 token | 视角2 的 4 个 token]  → 8 个 token
  视角 1 的 context = [视角0 的 4 个 token | 视角2 的 4 个 token]  → 8 个 token
  视角 2 的 context = [视角0 的 4 个 token | 视角1 的 4 个 token]  → 8 个 token

  → 每个视角的 Q 还是 4 个 token，K/V 变成 8 个 token
  → scores 形状 (4, 8)，而不是 (4, 4)

  关键规则：永远不把自己算进自己的 context（去掉对角线）

4.1 源码：怎么拼出来的

src/model/encoder/backbone/backbone_croco_multiview.py · 第 178–184 行 
178  def generate_ctx_views(x):                       # x 形状 (b, v, l, c)
179      b, v, l, c = x.shape
180      ctx_views = x.unsqueeze(1).expand(b, v, v, l, c)          # (b, v, v, l, c)
181      mask = torch.arange(v).unsqueeze(0) != torch.arange(v).unsqueeze(1)
182      ctx_views = ctx_views[:, mask].reshape(b, v, v - 1, l, c)  # (b, v, v-1, l, c)
183      ctx_views = ctx_views.flatten(2, 3)                        # (b, v, (v-1)*l, c)
184      return ctx_views.contiguous()
行代码讲解
180unsqueeze(1).expand(...) 先把每个视角复制 v 份 → 形状 (b, v, v, l, c)：第 2 个 v 是「给谁当 context」，第 3 个 v 是「谁的内容」。
181mask = arange(v) != arange(v) 造一个 v × v 的布尔表，对角线是 False（不相等才为 True）→ 去掉「自己当自己的 context」。
182ctx_views[:, mask].reshape(...) 按 mask 挑出非对角元素 → (b, v, v-1, l, c)：每个视角拿到 v−1 份别人的内容。
183flatten(2, 3) 把「v−1 个视角」和「每个视角 l 个 token」并成一维 → (b, v, (v-1)*l, c)。这就是拼接那一步。

4.2 于是 514 就来了

真实数字（v = 3 个视角）：

  每个视角的 token 数 l = 257 = 256 个 patch + 1 个相机内参 token
                              （512×512 输入时 patch 数是 1024，则 l = 1025；
                                代码注释里的 257 来自 256×256 的运行）

  每个视角的 context 长度 = (v − 1) × l = 2 × 257 = 514

  → Q 长度 257，K/V 长度 514，scores 形状 (257, 514)
  → 再分头：12 头 × 64 维 → attn 形状 [b, 12, 257, 514]   ← 源码注释里写的就是这个

5. 源码：CrossAttention 逐行

src/model/encoder/backbone/croco/blocks.py · 第 133–179 行 
133  class CrossAttention(nn.Module):
135      def __init__(self, dim, rope=None, num_heads=8, qkv_bias=False, attn_drop=0., proj_drop=0.):
137          self.num_heads = num_heads
138          head_dim = dim // num_heads
139          self.scale = head_dim ** -0.5
141          self.projq = nn.Linear(dim, dim, bias=qkv_bias)     # ← Q 自己的投影
142          self.projk = nn.Linear(dim, dim, bias=qkv_bias)     # ← K 自己的投影
143          self.projv = nn.Linear(dim, dim, bias=qkv_bias)     # ← V 自己的投影
145          self.proj  = nn.Linear(dim, dim)                    # 和 self-attention 一样的输出投影
148          self.rope = rope

150      def forward(self, query, key, value, qpos, kpos, mask=None):
151          B, Nq, C = query.shape          # ← query 的长度
152          Nk = key.shape[1]               # ← key 的长度（可以和 Nq 不同）
153          Nv = value.shape[1]             # ← value 的长度
155          q = self.projq(query).reshape(B,Nq,self.num_heads, C//self.num_heads).permute(0, 2, 1, 3)
156          k = self.projk(key).reshape(B,Nk,self.num_heads, C//self.num_heads).permute(0, 2, 1, 3)
157          v = self.projv(value).reshape(B,Nv,self.num_heads, C//self.num_heads).permute(0, 2, 1, 3)
              # 源码注释实测：q [1,12,257,64]   k [1,12,514,64]   v [1,12,514,64]
161          if self.rope is not None:
162              q = self.rope(q, qpos)      # ← Q 用【自己视角】的坐标
163              k = self.rope(k, kpos)      # ← K 用【context 视角】的坐标
165          attn = (q @ k.transpose(-2, -1)) * self.scale     # (b, 12, 257, 514)
168          if mask is not None:
171              attn = attn + mask.unsqueeze(1)               # EcoSplat 这条路径传的是 None
173          attn = attn.softmax(dim=-1)
176          x = (attn @ v).transpose(1, 2).reshape(B, Nq, C)  # ← 输出长度回到 Nq！
177          x = self.proj(x)
179          return x
行要点
141–143三个独立的 Linear。这是它和 Attention（第 88 行一个 qkv = Linear(dim, 3*dim)）最大的实现差别 —— 因为两个输入序列不同，没法合成一次矩阵乘。
151–153三个长度变量 Nq / Nk / Nv 分别取。self-attention 里三者必然相等，这里可以不等。
162–163RoPE 用了两套坐标：qpos 是本视角的网格坐标，kpos 是 context 的坐标。 这样网络知道「你在自己图的哪个位置、你在对方图的哪个位置」（Ch.04 详讲）。
176reshape(B, Nq, C) —— 输出的行数硬绑定 Nq。这就是 §1 里「输出跟着 query 走」的代码证据。

181  class DecoderBlock(nn.Module):
186      self.norm1 = norm_layer(dim)
187      self.attn  = Attention(dim, ...)          # ① 自己视角内部的 self-attention
188      self.cross_attn = CrossAttention(dim, ...)# ② 跨视角的 cross-attention
190      self.norm2 = norm_layer(dim)
191      self.norm3 = norm_layer(dim)
193      self.mlp   = Mlp(...)                    # ③ MLP
194      self.norm_y = norm_layer(dim) if norm_mem else nn.Identity()   # 给 context 用的 norm

196      def forward(self, x, y, xpos, ypos, mask=None):
            # x: (b, 257, 768)   y: (b, 514, 768)   xpos: (b, 257, 2)   ypos: (b, 514, 2)
199          x = x + self.drop_path(self.attn(self.norm1(x), xpos))
200          y_ = self.norm_y(y)
201          x = x + self.drop_path(self.cross_attn(self.norm2(x), y_, y_, xpos, ypos, mask))
202          x = x + self.drop_path(self.mlp(self.norm3(x)))
203          return x, y

和 Encoder 的 Block（Ch.02 §5）对照：

Encoder BlockDecoder Block
子层2 个：Self-Attn、MLP3 个：Self-Attn、Cross-Attn、MLP
LayerNorm2 个（norm1、norm2）3 个 + 1 个 norm_y（norm1 / norm2 / norm3，外加给 context 的 norm_y）
输入只有 xx（本视角）+ y（context 视角）
残差2 次3 次
顺序为什么是这样

先 self-attn：在自己这张图内部理一遍（哪些 patch 属于同一物体）。
再 cross-attn：带着整理好的信息去别的视角查（我这块在别人那儿对应哪）。
最后 MLP：把查回来的信息消化进自己的特征里。

norm_y 是对「别人的信息」单独做归一化（norm_mem=True 时）， 它不会更新 y —— return x, y 里 y 原样返回，整个 Decoder 里 context 的表示只在各处被读取、不被改写。

          final_output.append(torch.cat((f1, f2), dim=1))

【第 4 站】收尾
  self.dec_norm = LayerNorm(768)     最后再归一化一次
  输出：所有视角的特征 (b, v, l, 768)

7.1 用一句话说清整个过程（以 A / B / C 三个视角为例）

三张图各自变成一串 token，共用同一套 W_q、W_k、W_v。以 A 当查询方为例：

  • A 的 token 串 × W_q → Q
  • 把 B、C 的 token 串拼起来 → × W_k → K
  • 同一份拼接串 × W_v → V
    （V 不是由 Q、K 算出来的 —— 它和 K 用的是同一份输入，只是换了个权重，三者并列算出）
  • scores = Q·Kᵀ / √64 → 每行 softmax → 加权 V → 得到A 视角的输出特征（不是"V 本身"，V 只是中间量）

然后每个视角轮流当查询方，同样的事再做两遍：

轮次Q 来自K / V 来自输出
1AB + C 拼接（514）A 的输出（257）
2BA + C 拼接（514）B 的输出（257）
3CA + B 拼接（514）C 的输出（257）
三句补充
  1. 不是只做这三轮：每一层都做一遍，共 12 层（dec_depth = 12）→ 36 次 cross-attention。 而且每层在 cross-attention 之前，每个视角还要先做一次自己内部的 self-attention。
  2. 权重共享，但张量各算各的：W 是同一套，每个视角产生自己那份 Q/K/V。 唯一例外：视角 0 走 dec_blocks、视角 1+ 走 dec_blocks2，那一份权重不共享。
  3. context 每层重新拼：第 5 轮里 B 查到的，是已经被前 4 层更新过的 A —— 信息就这样逐层双向流动起来。
为什么有 dec_blocks 和 dec_blocks2 两份？

dec_blocks2 = deepcopy(dec_blocks)（第 85 行），两套独立权重。
因为输出是不对称的：视角 0 是参考帧，所有结果都要表达在它的坐标系里； 视角 1+ 是「被对齐到视角 0」的那一侧。两侧任务不同，所以用两套参数。
这也是这个类叫 AsymmetricCroCoMulti 的原因。

8. 【勘误 ②】是「两套 Transformer」吗？

你的想法：A、B 各自走两套 Transformer，有两套 QKV

这里必须先分清两件事：

权重（参数 W_q / W_k / W_v）激活值（张量 Q / K / V）
数量一套，所有视角共用（共享参数）每个视角各自一份
类比同一本《词典》，大家查同一本每个人查出来的结果各不相同
会不会被训练会不会，每次前向临时算出来

EcoSplat 的 Encoder 是 Siamese（孪生）结构：所有视角被展平进同一个 batch， 走同一个 patch_embed 和同一组 enc_blocks：

233    images_all = rearrange(images_all, "b v c h w -> (b v) c h w")    # 视角塞进 batch 维
237    feat, pos, P = self._encode_image(images_all, shape_all, intrinsic_embedding_all)
239    feat = rearrange(feat, "(b v) l c -> b v l c", b=b, v=v)           # 再拆回每个视角

所以「两套 QKV」这句话：

  • 如果指两套不同的参数 → 不对，权重是共享的（只有后面说的 dec_blocks2 例外）。
  • 如果指两份不同的 Q/K/V 张量 → 对，每个视角各自算一份。

8.1 「self-attention 时完全独立」——这句是对的

Encoder 阶段每个视角只跟自己玩：

视角 A：  Q = x_A·W_q    K = x_A·W_k    V = x_A·W_v      ← 全是 A 自己
视角 B：  Q = x_B·W_q    K = x_B·W_k    V = x_B·W_v      ← 全是 B 自己

两张图的 token 之间没有任何数值往来（这就是 Ch.02 结尾那句「视角之间此时还没说话」）。
之所以能这样批处理，正是因为大家共用同一组 W。

8.2 但 cross-attention 不是「两套 QKV 互相串」

Q 来自K 来自V 来自用的权重
Encoder self-attnx（本视角）x（本视角）x（本视角）融合的一个 qkv = Linear(dim, 3*dim)
Decoder self-attnx（本视角）x（本视角）x（本视角）同样是融合的 qkv
Decoder cross-attnx（本视角）y（其他视角）y（其他视角）三个独立 Linear：projq / projk / projv

在一次 cross-attention 里，只有查询方产生 Q，另一边只提供 K/V。 准确说法是「一个 Q（来自 x）+ 别人家的 K/V（来自 y）」， 而不是「两套 QKV 混合」。

那双向交流是怎么实现的？—— 轮流 + 多层迭代
  1. 每个视角轮流当查询方：视角 0 查「1+2」，视角 1 查「0+2」，视角 2 查「0+1」 （generate_ctx_views 干的就是这个）。
  2. context 每层重新生成（第 189 行 feat_current_ctx = generate_ctx_views(feat_current)）： 第 1 层 B 看到的是原始 A，第 5 层 B 看到的是「已经被前几层更新过的 A」。
  3. 重复 12 层（dec_depth = 12），就是 12 轮互相传阅。

类比：两个人各自写笔记（Encoder self-attn）→ 互相传阅并按对方内容修改自己的（Decoder cross-attn）→ 重复 12 轮。

唯一「真有两套权重」的地方

视角 0 走 dec_blocks，视角 1+ 走 dec_blocks2（deepcopy 出来的独立权重）。 因为两者任务不同：视角 0 是参考帧，所有输出都表达在它的坐标系里；视角 1+ 是被对齐的一方。
所以严格说，整套网络里只有 dec_blocks / dec_blocks2 这一处是"两套"。

9. 小结

  1. Cross-Attention = 换了个输入源的 Self-Attention：公式、softmax、缩放、多头全部一样， 只是 Q 来自 A、K/V 来自 B。
  2. scores 不再是方阵：形状是 (query 长度) × (context 长度)，这是最直观的识别特征。
  3. 输出长度跟着 query 走：进来 257 个 token，出去还是 257 个，变的是每个 token 里的内容。
  4. 多个 context 靠拼接：把所有其他视角首尾接成一条长序列，且永远排除自己 → 514 = 2 × 257。
  5. DecoderBlock 比 EncoderBlock 多一路：self-attn → cross-attn → MLP，三个残差、三个 LN + 一个 norm_y。
  6. 视角 0 和视角 1+ 用两套权重（dec_blocks / dec_blocks2），因为输出是「以视角 0 为参考系」的不对称设计。

自测

① 长度为 3 的 A 去 query 长度为 4 的 B，输出有多少个 token？

3 个。输出行数永远等于 query 的长度，与 context 多长无关。

② 为什么 cross-attention 要用三个独立 Linear，不能像 self-attention 那样合成一个？

因为 Q、K、V 来自两个不同的张量（query 和 key/value）， 没法用一次矩阵乘同时算出来。合成一个 Linear(dim, 3*dim) 的前提是三者输入相同。

③ v = 4 个视角、每视角 257 token 时，K/V 的长度是多少？

(4−1) × 257 = 771。scores 形状 (257, 771)。
